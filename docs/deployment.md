# ACME Salary Management — Deployment Architecture

## 1. Deployment Overview

The application consists of two independently deployable application layers:

```text
                  Internet
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
     Frontend                 API
     React/Vite              Express
          │                     │
          │                     ▼
          │                  Prisma
          │                     │
          │                     ▼
          │                   SQLite
          │
          └────── HTTP API ─────┘
```

---

## 2. Frontend Deployment

The frontend is a Vite application.

The production process is:

```text
Source Code
    ↓
npm install
    ↓
npm run build
    ↓
dist/
    ↓
Static Hosting
```

The frontend can be deployed to a static hosting platform capable of serving Vite builds.

Examples include platforms such as Vercel, Netlify, Cloudflare Pages, or similar static hosting providers.

---

## 3. Backend Deployment

The backend is a Node.js Express application.

The production process is conceptually:

```text
Source Code
    ↓
Install dependencies
    ↓
Prisma generate
    ↓
TypeScript build
    ↓
Node.js server
```

The API requires:

* Node.js runtime
* Environment variables
* Database access
* Persistent storage where SQLite is used

---

## 4. Environment Configuration

Environment-specific values must be configured outside source control.

The repository provides:

```text
.env.example
```

Developers should create their local `.env` from this template.

Production secrets must be configured through the deployment platform.

---

## 5. Database Deployment

The current project uses SQLite.

SQLite introduces an important deployment consideration:

**the database is a file.**

Therefore, the hosting environment must provide persistent storage.

Ephemeral server filesystems are unsuitable for persistent SQLite data.

---

## 6. Production Database Recommendation

For a real production enterprise deployment, PostgreSQL is recommended.

The preferred production architecture would become:

```text
React/Vite
     │
     ▼
Static Hosting
     │
     ▼
Express API
     │
     ▼
Prisma
     │
     ▼
Managed PostgreSQL
```

This provides better support for:

* Concurrent writes
* Multiple API instances
* Database backups
* High availability
* Operational monitoring
* Enterprise workloads

---

## 7. Build Validation

Before deployment:

```text
Install
  ↓
Generate Prisma Client
  ↓
Lint
  ↓
Typecheck
  ↓
Test
  ↓
Build
```

A deployment should not proceed if required validation fails.

---

## 8. Health Checks

A production API should expose a health endpoint such as:

```text
GET /health
```

A health check should verify that the application process is running.

A deeper readiness check can additionally verify database connectivity.

---

## 9. CORS Configuration

Production CORS should allow the deployed frontend origin.

Development may use:

```text
http://localhost:5173
```

Production should use the actual deployed frontend origin.

---

## 10. HTTPS

Production traffic should use HTTPS.

The deployment platform should terminate TLS or provide managed HTTPS.

---

## 11. CI/CD

The repository includes GitHub Actions workflow configuration.

The intended pipeline is:

```text
Push / Pull Request
       ↓
Install
       ↓
Validate
       ↓
Test
       ↓
Build
       ↓
Deploy
```

Deployment should occur only after required CI checks succeed.

---

## 12. Rollback Strategy

Deployment should be reversible.

If a release introduces a regression:

1. Identify the failing release.
2. Revert or redeploy the previous known-good version.
3. Verify health checks.
4. Investigate the failure.
5. Create a regression test if appropriate.
6. Deploy the corrected version.

---

## 13. Database Migrations

Database migrations must be treated as deployment artifacts.

A production migration should be:

* Version controlled
* Reviewed
* Tested
* Applied intentionally

Destructive migrations require additional review.

---

## 14. Static Assets

Frontend assets generated by Vite should be served through the frontend hosting layer.

Assets should not be served through the Express API unless there is a specific requirement.

---

## 15. Logging and Monitoring

Production deployment should include:

* Application logs
* API error monitoring
* Health checks
* Deployment status
* Database monitoring

Future improvements may include centralized observability tooling.

---

## 16. Deployment Security Checklist

Before production:

* [ ] HTTPS enabled
* [ ] Production environment variables configured
* [ ] Development secrets removed
* [ ] CORS restricted
* [ ] Database persistence verified
* [ ] Health checks configured
* [ ] CI passing
* [ ] Database backups configured
* [ ] Error responses reviewed
* [ ] Logs reviewed for sensitive information

---

## 17. Assessment Deployment Strategy

For the engineering assessment, simplicity is preferred.

The assessment deployment should prioritize:

* Reliable startup
* Reproducible seed data
* Easy demonstration
* Clear environment configuration
* Stable frontend/API communication

Production infrastructure should not be introduced unless it solves an actual requirement.
